# المظهر الليلي والنهاري · Theming (v1.6.0)

> ثلاثة أوضاع: **ليلي** (الهوية الأصلية) · **نهاري** · **تلقائي** يتبع إعداد الهاتف.
> الاختيار يُحفظ في `localStorage['mda.themeMode']` ويُطبَّق **قبل أول رسم** فلا يوجد وميض.

## 1. كيف يعمل بدون إعادة كتابة كل الشاشات؟

كل ألوان التطبيق تمرّ عبر متغيّرات CSS، والـ Tailwind يقرأ منها:

```js
// tailwind.config.js
ink:  { 950: 'rgb(var(--ink-950) / <alpha-value>)', … },
white: 'rgb(var(--white) / <alpha-value>)',   // ← حيلة الأساس
```

| العائلة | في الوضع الليلي | في الوضع النهاري | لماذا |
| --- | --- | --- | --- |
| `ink-950` | `#050c1a` | `#f4f8fd` | خلفية الصفحة |
| `ink-900` | `#0a1930` | `#ffffff` | سطح البطاقات |
| `ink-100` | `#e4ecf9` | `#112240` | النص الأساسي |
| `ink-400` | `#7f9dc9` | `#5c708c` | النص الثانوي |
| `ink-500` | `#5f7fae` | `#8294ac` | التلميحات |
| `white` | `255 255 255` | `15 23 42` | كل `bg-white/5` و`border-white/10` و`text-white` |

لأن `white` نفسه صار متغيّرًا، فإن **`bg-white/[.05]`** (وهي مستخدمة 128 مرة) تتحول تلقائيًا إلى طبقة داكنة شفافة 5% على الأبيض، و**`border-white/10`** تصبح خطًّا داكنًا، و**`text-white`** يصبح نصًّا داكنًا. لا حاجة لتعديل أي شاشة.

## 2. الاستثناءات (ثلاثة فقط)

| الحالة | الحل | الملف |
| --- | --- | --- |
| نص أبيض فوق **تدرّج ملوّن** (شعارات، أيقونات، أزرار) | الصنف `on-color` يُثبّت اللون `#fff` | `styles.css` |
| حقل أبيض حقيقي فوق الهيرو الأزرق | الصنف `bg-paper` (أبيض دائم) | `Home.tsx`, `Systems.tsx` |
| نصوص حالات فاتحة (`text-emerald-300`…) على خلفية بيضاء | إعادة تعيين إلى درجة 600/700 في الوضع النهاري | نفس الملف |

## 3. قواعد لكتابة شاشة جديدة

1. استخدم `text-ink-*` و`bg-ink-*` و`bg-white/[.0x]` — لا تكتب `bg-[#0a1930]` ولا `text-[#fff]`.
2. إذا كان السطح **مصبوغًا** (تدرّج/لون قوي) فالنص عليه `on-color`.
3. إذا كان العنصر يجب أن يبقى أبيض في الوضعين (حقل بحث، شعار على فيديو) فـ`bg-paper` / `on-color`.
4. لا تستخدم `dark:` — النظام يعمل بالمتغيّرات، و`dark:` سيتضاعف معها.
5. الظلال: `shadow-card` تتبع الوضع عبر `var(--shadow-card)`.

## 4. البداية الباردة (splash)

`index.html` يحتوي سكربتًا صغيرًا يقرأ الوضع ويضبط `data-theme` + `theme-color` **قبل** تحميل React، وشاشة الإقلاع لها نسختان (ليلي/نهاري) في نفس الملف. النتيجة: مستخدم الوضع النهاري لا يرى وميضًا داكنًا عند فتح التطبيق.

## 5. الاختبارات

```bash
npm run test:ui   # 35 تحققًا
```

- الافتراضي ليلي، و`<html data-theme="dark">` + `.dark` موجودان.
- التبديل إلى `light` يغيّر `data-theme` و`theme-color` ويحفظ الاختيار.
- `system` يتبع `matchMedia('(prefers-color-scheme: dark)')` (يُختبر بحالتين).
- الاختيار المحفوظ يبقى بعد إعادة التركيب.
- لا يتغيّر أي شيء قبل تركيب الـ Provider (لا وميض ألوان خاطئة).

## 6. حدود معلنة

- شاشة إقلاع أندرويد الأصلية (Splash) تبقى بالهوية الداكنة — تغييرها يحتاج صورة splash لكل وضع.
- ألوان المتصفح حول الصفحة (شريط النظام) تتبع `theme-color` على أندرويد الحديث فقط.
- الرسوم/الصور المضمّنة (أيقونات PNG) لا تتغيّر.
