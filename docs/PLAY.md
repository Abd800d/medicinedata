# الرفع إلى Google Play — قائمة تحقق كاملة (v1.8.0)

هذا الملف يجيب على سؤال واحد: **ما الذي أضغط عليه بالضبط، وبأي قيمة، حتى يُقبل التطبيق في المتجر من أول مرة؟**
كل قيمة مكتوبة هنا مأخوذة من التطبيق نفسه (لا وعود تسويقية)، وكل مسار ملف موجود في المستودع.

## ٠) قبل أي شيء: ما الذي يحتاجه Play فعليًا

| المطلوب | الحالة في هذا المستودع |
|---|---|
| حزمة `.aab` **موقّعة** | يُنتجها سير عمل Android عند وجود الأسرار الأربعة (القسم ١) |
| `targetSdk` = 35 (Android 15) | ✅ `android/variables.gradle` + بوابة «Verify SDK 35» في CI |
| أيقونة 512×512 PNG **بدون شفافية** | `store/icon-512.png` (512×512، colorType 2، 69,645 B) |
| صورة عرض 1024×500 بدون شفافية | `store/feature-graphic.png` (160,608 B) |
| لقطات شاشة للهاتف (٢ على الأقل) | تُلتقط من التطبيق المثبّت — القسم ٤ |
| رابط سياسة خصوصية يعمل بدون تسجيل | `/privacy` (HTML من الخادم، يعمل بدون JavaScript) |

## ١) المفتاح والبناء الموقّع (مرة واحدة)

### أ) إنشاء مفتاح الرفع من الهاتف (بدون Java)

1. سجّل الدخول كـ **مدير** → الإدارة → التكاملات → **«مفتاح رفع Google Play»**.
2. كلمة مرور 12+ حرفًا (زر «عشوائي» يملأها) → **إنشاء مفتاح الرفع**.
3. **تنزيل `mda-upload.p12`** + نسخ كلمة المرور في مدير كلمات مرور. الملف لا يُحفظ على الخادم.
4. الصفحة تعرض الأربعة أسماء مع زر نسخ — انتقل إلى:
   `github.com/Abd800d/medicinedata → Settings → Secrets and variables → Actions → New repository secret`

| Secret | القيمة |
|---|---|
| `ANDROID_KEYSTORE_BASE64` | محتوى الملف بعد ترميز base64 (زر «نسخ base64») |
| `ANDROID_KEYSTORE_PASSWORD` | كلمة المرور التي كتبتها |
| `ANDROID_KEY_ALIAS` | `mda-upload` |
| `ANDROID_KEY_PASSWORD` | نفس كلمة المرور |

بديل من الحاسوب: `npm run keystore -- --password 'كلمة-قوية'` ثم `gh secret set …` (يطبعها السكربت).

### ب) بناء الحزمة

```bash
git tag v1.8.0 && git push origin v1.8.0
```

سير العمل يبني ويوقّع **الاثنين**: `app-release.apk` (توزيع مباشر) و`app-release.aab` (Play)،
ويضعهما في **Releases** مع تقرير بصمة الشهادة في صفحة الـActions.

**قاعدة لا تُخترق:** كل رفع جديد يحتاج `versionCode` أكبر. القيمة الحالية مأخوذة من رقم التشغيل في CI،
أو من `-PversionCode=` يدويًا.

## ٣) النماذج التي تُرفض بسببها التطبيقات عادةً — وأجوبتها هنا

### أ) App access (وصول المراجعين)

اختر **«All or some functionality is restricted»** ثم أضف بيانات دخول حقيقية:

| الحقل | القيمة |
|---|---|
| Username | `reviewer@mda.app` (أنشئه من الإدارة → المستخدمون، الدور: صيدلي) |
| Password | كلمة مرور قوية تضعها أنت |
| Instructions | `Sign in with the email above. The medicine catalogue is readable without an account; prescriptions, AI analysis and the admin panel need the account.` |

بدون هذا الحقل يُرفض التطبيق تلقائيًا لأنه يحتوي شاشة تسجيل دخول.

### ب) Data safety — أمان البيانات

| السؤال | الجواب |
|---|---|
| Does your app collect or share any of the required user data types? | **Yes** |
| Personal info → Email address | Collected · لا يُشارك · الغرض: إدارة الحساب · مشفّر أثناء النقل · يمكن للمستخدم طلب الحذف |
| Personal info → Name | Collected (اختياري عند التسجيل) · لا يُشارك |
| Photos and videos → Photos | Collected (وصفة يرفعها المستخدم بنفسه) · لا يُشارك · يُحذف عند الحذف النهائي |
| Health info → (لا) | **No** — لا نجمع تشخيصًا ولا ملفًا طبيًا؛ الوصفة صورة يرفعها المستخدم ولها موافقة صريحة |
| App activity → Other user-generated content | Collected (المجتمع/الوظائف) · يُشارك مع مستخدمي التطبيق |
| Device or other IDs | **لا** — لا إعلانات ولا تحليلات ولا SDK تتبّع |
| Data encrypted in transit | ✅ HTTPS |
| Ways to request deletion | `DELETE /api/rx/:id` من داخل التطبيق + بريد الدعم؛ ومذكور في `/privacy` |
| Ads | **No ads** |
| Analytics | **No** |

### ج) Content rating (IARC)

الفئة: **Utility / Reference**. أجوبة مؤثرة:
- عنف/جنس/مخدرات/كحول/مقامرة: **لا** لكل ذلك.
- محتوى من المستخدمين (UGC): **نعم** (المجتمع + لوحة الوظائف) → يوجد إبلاغ وإدارة وحظر من لوحة الإدارة.
- مشاركة الموقع: **لا**. مشتريات داخلية: **لا**.
- الأسئلة الصحية: التطبيق **مرجع معلوماتي** ولا يقدّم نصيحة تشخيصية؛ أجب «لا» على تقديم استشارة طبية.

### د) Health apps / سياسات إضافية

- **Health apps declaration:** لا يستخدم Health Connect ولا يجمع بيانات صحية.
- **Medical disclaimer:** موجود في `/terms` البند ٣ وفي شاشة التحليل («لا اعتماد تلقائي» و«يحتاج إلى مراجعة الصيدلي»).
- **الأدوية:** لا بيع ولا توصيل ولا أسعار — التطبيق لا يوزّع أدوية.

## ٤) لقطات الشاشة (٢ على الأقل)

Play لا يقبل لقطات مُعاد رسمها أو مُصغّرة من المتصفح فقط؛ التقطها من التطبيق المثبّت:

1. ثبّت `app-release.apk` من صفحة Releases.
2. افتح: الرئيسية → الأدوية (بحث) → صفحة دواء → الوصفات (تحليل) → الإدارة.
3. لقطة: `Power + Volume Down`، ثم ‎٢‎–‎٦‎ صور فقط.
4. المقاس الموصى به: 1080×1920 (أو أي نسبة 9:16 بين 320 و3840 بكسل).
5. إن أردت إطارًا موحّدًا: ضع الصور في `store/screenshots-src/` ثم `npm run store:assets`
   (يضيف خلفية navy وشريط عنوان؛ نصوصه إنجليزية بسبب غياب الخط العربي في بيئة التوليد).

> منع لقطات الشاشة (FLAG_SECURE) يجب أن يكون **مطفأً** أثناء التصوير، ويمكن تفعيله بعدها من
> شاشة الوصفة نفسها (المفتاح الجديد في v1.8.0).

| المسار | متى | ملاحظات |
|---|---|---|
| Internal testing | فورًا | حتى 100 مُختبِر، مراجعة سريعة (دقائق)، لا تحتاج 12 مختبِرًا |
| Closed testing | قبل الإنتاج | **الحسابات الشخصية الجديدة** تحتاج 12 مختبِرًا لمدة 14 يومًا متصلة قبل طلب الوصول للإنتاج |

## ٦) التحقق قبل الرفع (٣ أوامر)

```bash
# 1) الحزمة موقّعة أم لا؟ (ينفّذه CI تلقائيًا، أو محليًا)
jarsigner -verify -verbose -certs app-release.aab | head -5   # يجب: jar verified

# 2) هل targetSdk = 35؟
aapt2 dump badging app-release.apk | grep -o "targetSdkVersion:'[0-9]*'"

# 3) هل الصفحتان تعملان بدون JavaScript؟
curl -s https://<your-host>/privacy | grep -c "سياسة الخصوصية"
curl -s https://<your-host>/terms   | grep -c "شروط الاستخدام"
```

## ٧) صيانة ما بعد النشر

- **تحديث الإصدار:** ارفع `versionCode` (تلقائيًا = رقم تشغيل CI)، وأنشئ وسمًا جديدًا.
- **إعادة تعيين مفتاح الرفع:** Play Console → App integrity → Manage Play app signing → طلب إعادة تعيين
  (لا يؤثر على المستخدمين لأن Google يوقّع النسخ النهائية بمفتاحه).
- **بيانات الاختبار تُحذف** من الإدارة → البيانات قبل النشر إن أردت بداية نظيفة (مع الحفاظ على الكتالوج).
