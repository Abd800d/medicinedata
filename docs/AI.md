# طبقة الذكاء الاصطناعي · AI layer (v1.8.1)

> «النموذج يقرأ، والصيدلي يقرر.» لا يوجد مسار في هذا النظام يسمح للنموذج باعتماد دواء أو جرعة أو تغيير وصفة.

## 1. البنية

```
التطبيق (Android/Web)
   │  لا مفاتيح، لا عناوين مزوّدين
   ▼
POST /api/rx/analyze  ──►  authRequired  ──►  consent gate (428)
   │                          │
   │                          ├─ multer (12MB, images only)
   │                          ▼
   │                    lib/ai/prescription.js
   │                      analyzePrescription()
   │                        ├─ lib/ai/prompts.js  (تعليمات ثابتة)
   │                        ├─ lib/ai/service.js  (النقل/المهلة/الإعادة/السجل)
   │                        ├─ validateAnalysis() (شكل صارم + ثقة لكل حقل)
   │                        └─ enrich()           (مطابقة + dossier + flags)
   ▼
SQLite: prescriptions · prescription_items · ai_runs · prescription_reviews · audit_log
```

| ملف | المسؤولية | لا يفعل |
| --- | --- | --- |
| `server/lib/ai/service.js` | مزوّد واحد بواجهة OpenAI-compatible، مهلة، إعادة محاولة، تسجيل | لا يعرف الوصفات ولا يفسّر مخرجات |
| `server/lib/ai/prompts.js` | نصوص التعليمات والمخطط (data لا code) | لا يجمع طلبات ديناميكيًا |
| `server/lib/ai/prescription.js` | تحقق + إثراء + تجميع | لا يتصل بالشبكة مباشرة |
| `server/lib/ai/match.js` | مطابقة الاسم مع قاعدة MDA + الجرعات + التنبيهات | لا يخترع دواءً غير موجود |
| `server/lib/audit.js` | سجل تجزئة متسلسل + الموافقات | لا يحذف شيئًا |

## 2. المزوّدون

متغيرات البيئة على الخادم فقط:

| المتغيّر | القيمة | ملاحظة |
| --- | --- | --- |
| `AI_PROVIDER` | `groq` \| `openai` \| `gemini` \| `openrouter` \| `together` \| `deepseek` \| `ollama` | Groq هو الافتراضي المجاني |
| `AI_API_KEY` | المفتاح | **لا يُرسل للعميل أبدًا** |
| `AI_BASE_URL` | اختياري | لاستخدام مزوّد مخصّص/compatible |
| `AI_MODEL` | `llama-3.3-70b-versatile` | نصوص |
| `AI_VISION_MODEL` | `meta-llama/llama-4-scout-17b-16e-instruct` | صور |
| `AI_TIMEOUT_MS` | `45000` | مهلة كل محاولة |
| `AI_RETRIES` | `2` | إعادة بمهلة أسّية + jitter |

- `GET /api/rx/status` يعيد `configured`, `provider`, `model`, `vision_model`, `prompt_version` فقط — لا مفتاح، لا عنوان URL.
- لو لم يُضبط المفتاح: كل المسارات تُرجع `503 AI_NOT_CONFIGURED` مع رسالة عربية واضحة، وبقية التطبيق يعمل طبيعيًا.

## 4. المخطط والثقة

`PRESCRIPTION_SCHEMA` (في `prompts.js`) يفرض:

```json
{ "readable": bool, "image_quality": "good|fair|poor", "language": "ar|en|mixed",
  "patient": {"name": string|null, "confidence": 0..1}, "doctor": {...}, "clinic": {...}, "date": {...},
  "items": [{ "raw_text", "name", "name_ar", "strength", "form", "dose", "frequency",
              "duration", "route", "instructions", "confidence", "uncertain_fields": [] }],
  "notes": string|null, "warnings": [string] }
```

قواعد التحقق في `validateAnalysis()`:

1. أي حقل فارغ/`"غير محدد"`/`"n/a"` ⇒ `null` وثقته **0** (لا يبدو واثقًا وهو فارغ).
2. `FIELD_THRESHOLD = 0.55`: أي حقل ثقته أقل يُضاف إلى `uncertain_fields` تلقائيًا.
3. `ITEM_THRESHOLD = 0.7`: البند يُعلَّم `needs_review`.
4. `auto_accepted = 0` **دائمًا** و`requires_pharmacist = true`.
5. الحد الأقصى 25 بندًا في التحليل الواحد.

## 5. الحساسيات المسجّلة (v1.3.0)

النظام لا يستنتج حساسية من أي مصدر. المستخدم يسجّل الحساسية بنفسه، والتنبيه يُبنى على التقاء معلومتين موثّقتين:

1. **قائمة المستخدم** (`user_allergies`): إمّا `mol:<generic_name>` لمادة فعالة محددة، أو كود عائلة من `server/data/allergens.js`.
2. **تصنيف الدواء**: العائلات تُشتق من **كود ATC** (WHO) مع قائمة أسماء صريحة عند الحاجة، لا من اسم تجاري ولا من تشابه نصي.

| الحالة | التنبيه | الشدّة |
| --- | --- | --- |
| تطابق المادة الفعالة نفسها | «حساسية مسجّلة لنفس الدواء» | عالية |
| تطابق عائلة موثّقة (مثل البنسلينات) | «حساسية مسجّلة من نفس العائلة الدوائية» | عالية |
| لا تطابق | لا تنبيه — ولا ندّعي أنه «آمن» | — |

- 69 عائلة دوائية موثّقة (بيتا-لاكتام، سلفوناميد، NSAID، مضادات الصرع العطرية، وسائط التباين…).
- لكل دواء `allergen_families` تُعرض في بطاقة الدواء نفسها.
- **لقطة اللقطة**: تُحفظ الحساسيات المفحوصة مع الوصفة (`patient_context_json`) حتى لو عدّل المستخدم قائمته لاحقًا، فيرى الصيدلي نفس الحقائق التي بُني عليها التنبيه.

## 6. الإثراء من قاعدة MDA

`enrich()` يضيف لكل بند:

- `matched` (أفضل مرشّح: منتج تجاري أو مادة فعالة) + `alternatives` (حتى 6 مرشّحين).
- `dossier`: المادة الفعالة، الفئة، ATC، دواعي الاستعمال، الجرعة المرجعية، موانع الاستعمال، التحذيرات، التداخلات، الحمل، **المصدر وتاريخ آخر تحديث**.
- `dose_calc`: حساب الجرعة اليومية بالملغ فقط عند وجود رقمين مقروءين (جرعة + تركيز).
- `review_flags` من بيانات محفوظة فقط:
  | النوع | متى | الصياغة |
  | --- | --- | --- |
  | `duplicate_ingredient` | نفس المادة الفعالة في أكثر من سطر | «يحتاج إلى مراجعة الصيدلي» |
  | `dose_above_max` | المحسوب > المرجع × 1.05 | «يحتاج إلى مراجعة الصيدلي/الطبيب» |
  | `possible_interaction` | اسم الدواء الآخر مذكور في حقل التداخلات | «يحتاج إلى مراجعة الصيدلي» |
  | `duplicate_therapy_class` | دواءان مختلفان بنفس `drug_class` | «يحتاج إلى مراجعة الصيدلي» |
  | `allergy_conflict` | تطابق مادة أو عائلة مع حساسية مسجّلة | «مراجعة قبل الصرف» |
  | `unmatched_items` | بند بلا مطابقة | تصحيح يدوي مطلوب |
  | `data_missing` | لا تداخلات ولا تحذيرات محفوظة | «غياب التحذير لا يعني السلامة» |

- **كل تنبيه يحمل أربع طبقات**: `detail_*` (ما تقوله القاعدة)، `plain_*` (بلغة يومية)، `why_*` (السبب الحرفي: أي حقل وأي كود ATC)، و`source` (المصدر وتاريخ آخر تحديث). الواجهة تعرض الشرح المبسّط أولًا، والسبب تحت زر «لماذا ظهر هذا التنبيه؟».

لا يوجد أي تنبيه مُخترع: إن لم تكن المعلومة في القاعدة، لا يُقال شيء.

## 7. دورة المراجعة

```
pending_review ──(صيدلي: تصحيح بند)──► البند corrected
      │
      ├──(POST confirm, وكل البنود غير pending)──► reviewed + prescription_reviews(approved)
      ├──(POST confirm مع accept_uncertain)──────► reviewed (موثّق أنه تجاوز بشري صريح)
      └──(POST reject + سبب)─────────────────────► rejected
```

- التأكيد محجوب `409` ما دام أي بند `pending` — لا يمكن «الموافقة الشاملة» بالخطأ.
- كل تصحيح يخزّن `corrected_by` و`corrected_at`، وكل الإجراءات تُكتب في `audit_log` بسلسلة تجزئة.

## 9. حدود معلنة

- **لا OCR على الجهاز**: بدون إنترنت لا تحليل (يظهر تنبيه). السبب: لا نموذج مضمّن في APK.
- **لا تحسين صور على الخادم** في هذه النسخة: التحسين (قص/دوران/تباين) مسؤولية الكاميرا والمستخدم الآن؛ معالجة الصور المضغوطة/المائلة تبدأ في v1.5.0.
- النماذج المجانية قد تفشل أو تتأخر؛ لذلك مهلة + إعادة محاولة + رسالة قابلة للفهم + إمكانية الإدخال اليدوي.
- لا يوجد ضمان على دقة النموذج؛ الضمان الوحيد هو أن **القرار لا يُتخذ آليًا**.
- تنبيه الحساسية **ليس تشخيصًا**: قد تكون الحساسية المسجّلة خاطئة أو غير مكتملة، والحساسية المتصالبة ليست مؤكدة لكل مريض — لذلك الصياغة دائمًا «راجع الصيدلي».
- لا نغطّي الحساسية من مكوّنات غير دوائية (سواغات، أصباغ) لعدم توفر بياناتها في القاعدة.

## التفعيل من داخل التطبيق (v1.8.1)

المشكلة التي كانت قائمة: تفعيل الذكاء الاصطناعي يحتاج تعديل `.env` على الخادم وإعادة تشغيله،
وهو غير ممكن من الهاتف — فيرى المستخدم «الذكاء الاصطناعي لا يعمل» بلا سبب واضح ولا حل.

الآن هناك مسار كامل من الهاتف: **الإدارة ← الذكاء الاصطناعي** (اختصار: `/admin?tab=ai`).

| الطبقة | الملف | المسؤولية |
|---|---|---|
| إعدادات المزوّدين | `server/lib/ai/providers.js` | قوالب جاهزة: Groq، Gemini، OpenAI، OpenRouter، Together، DeepSeek، Ollama، مخصص |
| الإعداد المتغيّر | `server/lib/ai-config.js` | قراءة/كتابة الإعداد، الأولوية، الاختبار الذاتي، تصنيف الأخطاء |
| التشفير عند التخزين | `server/lib/secrets.js` | AES‑256‑GCM بمفتاح مشتق من `JWT_SECRET` (scrypt) |
| الواجهة | `src/pages/admin/AiSettings.tsx` | اختيار المزوّد، لصق المفتاح، اختبار حقيقي، دليل مفعّل |

### أولوية الإعداد
1. ما يحفظه المدير من التطبيق (جدول `settings`، مشفّرًا).
2. متغيّرات البيئة `AI_PROVIDER` / `AI_BASE_URL` / `AI_MODEL` / `AI_VISION_MODEL` / `AI_API_KEY`.
3. قالب المزوّد الافتراضي.

يُقرأ الإعداد **عند كل طلب**، فلا حاجة لإعادة تشغيل الخادم بعد التغيير.

### الاختبار الذاتي `POST /api/admin/ai/test`
يُنفّذ استدعاءً حقيقيًا صغيرًا (`max_tokens: 8`) ويعيد تصنيفًا صريحًا بدل «خطأ عام»:

| kind | المعنى | ما يفعله المدير |
|---|---|---|
| `auth` | مفتاح خاطئ/منتهٍ (401/403) | إنشاء مفتاح جديد من رابط المزوّد |
| `model` | اسم موديل غير متاح | إرجاع الموديل الافتراضي |
| `quota` | تجاوز الحصة المجانية (429) | الانتظار أو مزوّد آخر |
| `request` | المزوّد رفض الصيغة (400) | موديل يدعم JSON أو مزوّد آخر |
| `network` / `timeout` | الخادم لا يصل للمزوّد | فحص العنوان واتصال الخادم |
| `no-key` | لا مفتاح | لصق المفتاح أولًا |

## كيف تضيف الذكاء الاصطناعي إلى التطبيق (v1.10.2)

الذكاء الاصطناعي **مبني داخل التطبيق** لا مضافة خارجية: ثلاث شاشات تستخدمه، ولا شيء منها يحتاج مفتاحًا في الهاتف.
الخطوة الوحيدة الناقصة على أي تثبيت جديد هي **مفتاح مزوّد واحد** يُخزَّن على الخادم.

### الطريق الأقصر (من الهاتف، دقيقتان)

| # | الخطوة | ما تراه |
| --- | --- | --- |
| 1 | سجّل الدخول بحساب المالك (`7a8b1d@gmail.com`) | — |
| 2 | **المزيد ← الإدارة ← جودة التحليل** (`/admin?tab=ai`) | بطاقة «الذكاء الاصطناعي — التفعيل من الهاتف» |
| 3 | اضغط **Groq (مجاني)** أو **Google Gemini (مجاني)** | يمتلئ العنوان والموديلات من القالب |

| 5 | الصق المفتاح في «مفتاح API» ← **حفظ** | «حُفظت الإعدادات — الذكاء الاصطناعي مفعّل» |

بعد الحفظ لا حاجة لإعادة تشغيل الخادم ولا لإعادة تثبيت التطبيق: الإعداد يُقرأ عند كل طلب.

### الموديلات الحالية (v1.10.2)

الموديلات القديمة في القوالب كانت ميتة، ولهذا كان الاختبار يفشل بـ `model` رغم صحة المفتاح:

| المزوّد | الافتراضي الآن | بدائل جاهزة في الشاشة | الميت (لا تستخدمه) |
| --- | --- | --- | --- |
| Groq | `openai/gpt-oss-120b` | `openai/gpt-oss-20b` | `llama-3.3-70b-versatile` (أوقف 2026-08-16)، `llama-3.1-8b-instant` |
| Gemini | `gemini-3.6-flash` | `gemini-3.8-flash`، `gemini-3.1-flash-lite` | `gemini-2.0-flash` (أُغلق 2026-06-01) |

يظهر تنبيه أحمر في الشاشة مع زر **«استخدم البديل الآن»**، والاختبار المستقل يمنع أن يُشحن قالب ميت مرة أخرى.

### إصلاح `NO_SECRET` (كان يمنع التفعيل على أي خادم بلا `JWT_SECRET`)

كان `server/lib/secrets.js` يقرأ `process.env.JWT_SECRET` فقط، بينما `server/auth.js` يقبل سرًّا محفوظًا في
`settings.jwt_secret`. النتيجة: تثبيت بلا متغيّر بيئة **يسجّل الدخول بنجاح** لكنه يرفض حفظ المفتاح:

```
PUT /api/admin/ai → 400 {"error":"NO_SECRET","message":"الخادم بلا JWT_SECRET — لا يمكن تشفير المفتاح"}
```

الآن يُشتق مفتاح التشفير من نفس مادة `auth.js`: متغير البيئة أولًا، ثم السر المحفوظ، ثم يُولَّد ويُحفظ تلقائيًا
(بـ `INSERT OR IGNORE` كي يتفق عمليتان تقلعان معًا). النتيجة المقيسة على خادم **بلا** `JWT_SECRET`:

```
GET  /api/admin/ai → can_store = True
PUT  /api/admin/ai → HTTP 200  configured=True key_hint=gsk_…3456
# بعد إعادة تشغيل الخادم على نفس القاعدة:
GET  /api/admin/ai → has_key=True key_source=database   ← المفتاح ما زال صالحًا
```

| **الوصفات** (`/prescriptions`) | صورة وصفة → بنود + جرعات + تنبيهات حساسية، ثم طابور مراجعة صيدلي | نعم للتحليل |
| **المسح** (`/scan`) | صورة علبة → أقرب منتجات في القاعدة | نعم للتعرّف |

بدون مفتاح لا تظهر أخطاء: بطاقة `AiSetupHint` تشرح السبب وتضع للمدير زر «تفعيل الآن».

### تشخيص سريع

```bash
npm run doctor        # سطر «AI can be enabled from the app» → can_store / configured / model / model_warning
curl -s localhost:4000/api/ai/status
curl -s localhost:4000/api/rx/status
```

| الحالة | المعنى | الحل |
| --- | --- | --- |
| `can_store=false` | لا مادة لتشفير المفتاح | تأكد أن `data/` قابل للكتابة (أو اضبط `JWT_SECRET`) |
| `configured=false` + `has_key=true` | المفتاح موجود لكن العنوان/الموديل ناقص | أعد اختيار المزوّد ثم احفظ |
| `model_warning` ظاهر | الموديل مسحوب | زر «استخدم البديل الآن» |
| الاختبار `model` | الموديل غير متاح للمفتاح | اختر موديلًا من الأزرار المقترحة |
| الاختبار `auth` | المفتاح خاطئ/منتهٍ | مفتاح جديد |
| الاختبار `quota` | حصة مجانية | انتظر أو مزوّد آخر |

### الخصوصية
- المفتاح **لا** يُعاد أبدًا لأي عميل: `GET /api/admin/ai` يعيد `has_key` و`key_hint` فقط (`gsk_…cdef`).
- `GET /api/ai/status` و`GET /api/rx/status` عامّان ولا يحتويان أي مفتاح أو عنوان مزوّد أو حتى اسم حقول حسّاسة.
- كل تغيير أو اختبار يُسجَّل في سجل التدقيق (`ai.configure` / `ai.test`) بالمزوّد والموديل والنتيجة — بلا محتوى طلبات.
- عند غياب `JWT_SECRET` يرفض الخادم تخزين المفتاح (`NO_SECRET`) بدل تخزينه بلا تشفير.
