# تقرير أمني · Security review (v1.6.0)

> هذا تقرير **صادق بحدوده**: ما هو منفّذ فعليًا في الشيفرة، وما هو مقبول كحدّ معلن، وما لم يُنفّذ بعد. لا نكتب «مؤمّن بالكامل» لأن ذلك غير صحيح لأي تطبيق.

## 1. ما هو منفّذ

| الضابط | التنفيذ | الملف |
| --- | --- | --- |
| لا أسرار في التطبيق | كل مفاتيح AI/Google/الاستضافة في متغيرات بيئة الخادم | `server/lib/ai/service.js` |
| حظر تسريب الأسرار للعميل | حزمة الأوفلاين تبني إعدادات **بقائمة بيضاء** وتفشل البناء عند وجود مفتاح حسّاس | `scripts/build-offline-bundle.mjs` |
| سرّ JWT لكل نشر | `process.env.JWT_SECRET` أو سرّ عشوائي 48 بايت لكل قاعدة بيانات | `server/auth.js` |
| كلمات المرور | bcrypt (لا تُعاد أبدًا في الاستجابات) | `server/auth.js` |
| الأدوار | `user` / `pharmacist` / `admin`، والتحقق من الدور على الخادم في كل طلب | `server/auth.js` |
| ملكية البيانات | المستخدم يرى وصفاته فقط؛ الطاقم يرى الوصفة عند فتحها **ويُسجَّل** | `server/routes/prescription-ai.js` |
| موافقة صريحة | رفض 428 قبل أي رفع صورة، وموافقة بإصدار وتاريخ وقابلة للسحب | `user_consents` |
| حساسيات لا تُستنتج | إدخال يدوي فقط، أكواد مُتحقَّق منها، وحذف فوري متاح | `server/data/allergens.js` + `/api/rx/allergies` |
| عدم الاحتفاظ الافتراضي | الصورة تُحذف فور التحليل ما لم يطلب المستخدم حفظها | `POST /api/rx/analyze` |
| حق المحو | حذف الصورة + اسم المريض/الطبيب + النص + `raw_text`، وإبقاء أثر التدقيق فقط | `DELETE /api/rx/:id` |
| سجل غير قابل للتعديل | `audit_log` بسلسلة SHA-256 (`prev_hash` → `hash`) + `GET /api/admin/audit/verify` | `server/lib/audit.js` |
| لا اعتماد آلي | `auto_accepted = 0` و`requires_pharmacist = true` في كل تحليل | `prescription.js` |
| تحديد المعدّل | 12 تحليلًا/دقيقة و8 إعادة تحليل/دقيقة لكل مستخدم | `prescription-ai.js` |
| نوع الملف والحجم | صور فقط، 12 ميجابايت | `server/lib/upload.js` |
| عدم تسريب تفاصيل الأخطاء | رسائل مزوّد AI تُطبَع على الخادم فقط؛ العميل يستلم رمزًا ورسالة عربية | `service.js` |
| عدم تسجيل بيانات المرضى | `ai_runs` و`audit_log` تحمل معرّفات وأرقامًا فقط، لا نصوص وصفات | `prescription-ai.js` |
| طلب التوكن | `authRequired` على كل مسار وصفات، Token يُقرأ من الرأس فقط | `auth.js` |
| قفل التطبيق | رقم سري 4–8 أرقام، **PBKDF2‑SHA256 (150,000 دورة + ملح 16 بايت)**، لا يُرسل للخادم أبدًا | `src/lib/lockCrypto.ts` |
| تأخير بعد المحاولات | تصاعدي: 4 محاولات حرة → 30ث → 2د → 5د → 15د، محفوظ في الجهاز | `backoffMs()` |
| قفل تلقائي | عند مغادرة التطبيق (فوري أو بعد 1/5/15/60 دقيقة حسب اختيار المستخدم) | `src/lib/lock.tsx` |
| بصمة/وجه (اختياري) | WebAuthn platform authenticator محليًا كإيماءة تحقق، مع بقاء الرقم بديلًا | `registerBiometric()` |
| مسح عند نسيان الرقم | «نسيت الرقم» = خروج + حذف القفل والبيانات المحلية للجهاز (لا يمس بيانات الخادم) | `LockScreen.tsx` |
| نسخ احتياطية مشفّرة | AES‑256‑GCM + scrypt، ومعاملة استعادة واحدة مع نسخة أمان | `server/lib/backup.js` |
| تصدير بلا أسرار | مجموعات بيضاء؛ لا `password_hash` ولا نصوص وصفات ولا مفاتيح idempotency | `server/lib/exporter.js` |

## 2. حدود معلنة (بشفافية)

| البند | الحالة | الأثر | خطة |
| --- | --- | --- | --- |
| تشفير قاعدة SQLite على القرص | **غير منفّذ** (SQLCipher يحتاج بناء أصلي) | من يملك ملف الخادم يقرأه | النسخ الاحتياطية مشفّرة (v1.5)؛ التشفير الكامل مؤجّل لقرار النشر |
| منع لقطات الشاشة | **غير منفّذ** | يمكن تصوير شاشة الوصفة | `FLAG_SECURE` في تحديث أندرويد (يحتاج بناء APK أصلي) |
| قفل PIN/Biometric | ✅ **منفّذ في v1.6** | يحمي من «شخص أخذ الهاتف»؛ لا يحمي من جهاز مروّت أو تفريغ جنائي لـ localStorage | يكفي للاستخدام العادي؛ يُذكر الحد في شاشة القفل |
| WAF / CDN حماية | **غير منفّذ** | تعرّض مباشر لخدمة Render | يُوصى بـ Cloudflare أمام الدومين |
| اختبار اختراق معتمد | **لم يُجرَ** | لا شهادة | مراجعة خارجية قبل الإنتاج الواسع |
| ML Kit / OCR على الجهاز | **غير منفّذ** (قرار مقصود) | يحتاج إنترنت | بديل مستقبلي اختياري |
| JWT لكل جلسة قابلة للإبطال | **جزئي** | `active=0` يمنع الدخول لكن التوكن الحالي يبقى صالحًا حتى انتهائه | v1.4 دوال تحديث/إبطال |
| تدوير المفاتيح | يدوي | لا تدوير تلقائي | موثّق في `docs/ENV.md` |
| تشفير الصور على القرص | **غير منفّذ** | صور محفوظة باختيار المستخدم غير مشفّرة على القرص | v1.5 |
| الحساسيات = بيانات صحية | محمية بالحساب + قفل التطبيق | من يفتح الجهاز ورقم القفل يعرف يستطيع رؤيتها | قفل التطبيق في v1.6 يغطي الحالة الواقعية |

## 5. إعداد آمن للنشر (قائمة تحقق)

1. `JWT_SECRET` قيمة عشوائية 64 حرفًا (لا تُستخدم القيمة الافتراضية).
2. `AI_API_KEY` في Render → Environment، بلا مشاركة في المحادثات.
3. `GOOGLE_CLIENT_ID` في الإعدادات (عام — لا مشكلة في ظهوره).
4. دومين HTTPS + HSTS (Render يوفّره) + Cloudflare اختياري.
5. نسخ احتياطي يومي لـ `data/` وتشفيره قبل الخروج من الخادم.
6. مراجعة `GET /api/admin/audit/verify` أسبوعيًا — `ok:false` يعني تعديلًا خارجيًا.
7. تعطيل التحليل ببساطة عبر إزالة `AI_API_KEY` عند عدم الحاجة.
8. تدوير المفتاح: توليد مفتاح جديد عند المزوّد → تحديث `AI_API_KEY` → إعادة نشر → حذف القديم عند المزوّد.

## 6. ما يجب أن يبقى في الذهن

- **السجل يعتمد الثقة في الخادم**: من يملك ملف قاعدة البيانات ويمكنه تشغيل SQLite يستطيع إعادة بناء السلسلة. السلسلة تكشف التعديل الأعمى، لا الخصم الذي يملك الخادم.
- **مزوّد الذكاء الاصطناعي طرف ثالث**: الصورة تخرج من خادمك؛ لذلك الموافقة إلزامية، والحفظ الافتراضي معطّل.
- **الحماية الحقيقية للبيانات الصحية تبدأ من تقليل جمعها**، وهذا ما فُعِل: لا نحفظ الصورة إلا بطلب، ولا نضع اسم المريض في أي سجل أو قائمة.
